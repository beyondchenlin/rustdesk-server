## 实现及默认行为
- 新增独立 SQLite（嵌入式数据库）配置日志，支持版本、候选、确认、恢复和回滚；版本比较并交换，单运行时持有者锁，不覆盖旧数据库。
- 真实转发探测结果和已提交配置分离。候选全部不健康时拒绝发布；实际选择与候选不一致时拒绝确认；全节点故障时托管节点池不再分配已知失败节点，保留持久配置。
- 设备识别服务重新启动后恢复持久化版本并重新探测，未确认事务按已提交版本恢复。探测并发最多四个节点，每池最多十六个节点，单节点最多八个解析地址。周期检查为六十秒，健康结果有效期为一百五十秒。
- 托管模式通过 --bk-relay-pool 和 --bk-relay-admin-token-file 同时启用；不指定时保留原版路径。托管模式不接受同时设置原版 relay-servers 或 mask，原版 rs、aur 修改命令不能绕过托管管理。
- 管理只复用本地环回控制台，不增加对公网开放的管理端口。HMAC-SHA256（消息认证）双向挑战，分离管理员令牌与公开中继准入密钥，拒绝相等值。管理员令牌单独生成，不覆盖已有文件。命令中的操作者名称是审计标签，不是个人身份认证证明。
- 公开准入密钥正确接受、错误拒绝与真实转发测试不是中继私钥持有证明，不冒充密码学服务器身份验证。周期错误密钥探测产生的日志及负载仍需生产规模检查。
- 无新增外部依赖，不改 Cargo.lock（依赖锁文件）；未修改客户端协议。

## 本机操作方式
使用 bk-remote-relayctl（中继管理命令）：
- init-config：创建新的配置日志及初始节点列表。
- init-token：创建独立管理员令牌文件。
- config-status：读取持久配置和历史探测，不代表运行时已经检查。
- admin + 本机控制台端口 + 令牌文件 + status / publish / rollback / recover / refresh：查询、按期望版本发布、回滚、恢复或刷新健康状态。
- publish、rollback 必须提交期望当前版本；旧版本冲突直接拒绝。
- 管理令牌文件、配置库及其日志目录须仅授权服务账号和管理员访问。正式部署前核查 Linux（服务器操作系统）权限及 Windows（桌面操作系统）文件访问控制。不要把令牌提交仓库、放进客户端或当成公开中继密钥。
- 关闭托管模式并恢复之前的原版启动参数是部署级回滚路线，尚需正式环境演练；不可直接覆盖原数据库。
